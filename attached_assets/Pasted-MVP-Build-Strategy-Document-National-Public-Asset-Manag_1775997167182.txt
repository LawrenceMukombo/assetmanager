MVP Build Strategy Document
National Public Asset Management System (NPAMS)
Practical First-Build Roadmap for Lean Development

Prepared: April 2026

1. Document Purpose

This document converts the full enterprise NPAMS concept into a practical Minimum Viable Product (MVP) strategy for early-stage development.

Its purpose is to answer:

What should be built first?
What should be postponed?
How can the product be launched quickly?
How can risk and development cost be reduced?
How can the MVP validate market demand before full investment?

This approach follows Lean Startup principles, where an initial functional version is released quickly to validate assumptions before scaling (Ries, 2011).

2. Why an MVP is Critical

Building the full enterprise version immediately introduces high risk:

Risk	Explanation
Overbuilding	Creating features no one may use
Financial Risk	Large upfront development cost
Time Risk	Long build before testing market
Scope Creep	Endless additions delaying launch
Complexity	Difficult for first users to adopt
Strategic Principle:

Build only enough to prove value and secure adoption.

3. MVP Objective

The MVP must prove one thing:

That government institutions will adopt and pay for a digital asset management platform.

Everything else is secondary.

4. MVP Scope Philosophy

The MVP should focus on the single most painful user problem:

“Tracking and managing assets digitally instead of manually.”

NOT trying to solve every asset governance challenge immediately.

5. Recommended MVP Features (Phase 1 Build)

Only include the essential modules:

Module 1: User Authentication

Features:

Login/logout
Password reset
Basic RBAC
Module 2: Province-Based Multi-Tenancy

Features:

Province-specific login scope
National vs provincial visibility
Tenant filtering
Module 3: Asset Registry

Features:

Create/edit/delete asset
Assign category
Assign location
Assign custodian
Module 4: QR / Barcode Generation

Features:

Auto-generate QR code
Download/print labels
Module 5: Asset Search / Filtering

Features:

Search by asset name/tag
Filter by category/location/status
Module 6: Dashboard

Features:

Total assets
Missing assets
Assets by category
Asset value summary
Module 7: Reports Export

Features:

Export asset register PDF/Excel
Export filtered reports
6. Excluded from MVP (Build Later)

DO NOT BUILD YET:

Feature	Why Delay
Maintenance Module	Nice-to-have later
GIS Mapping	High complexity
Mobile App	Web responsive enough first
Offline Sync	Advanced requirement
Audit Workflows	Phase 2
Notifications	Can wait
Disposal Workflow	Later
Transfer Workflow	Later
AI Analytics	Far future
7. MVP Architecture Simplification

Reduce complexity for initial launch.

Recommended Lean Stack
Layer	Stack
Frontend	Next.js
Backend	Supabase / Node.js
Database	PostgreSQL
Hosting	Vercel / DigitalOcean
File Storage	Supabase Storage / S3
QR Generator	Open-source library
Why This Stack?

Because it enables:

Fast development
Low cost
Easy deployment
Minimal DevOps burden
